# Decisions

v3 is written from scratch. Nothing is carried over from v1 or v2.

## Shape

| ID  | Decision                                                                                                        | Reason                                                                                                                 |
| --- | --------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| A1  | The matcher is a set of pure functions over plain data: `handleKey`, `advanceTime`, `interrupt`, `nextDeadline` | Every behavior is testable without a DOM, a clock or React. v1 grew complex where state, timers and the DOM were mixed |
| A2  | Time is an argument, never read inside the core                                                                 | A driver runs one `setTimeout` aimed at `nextDeadline`. Tests pass times directly instead of faking timers             |
| A3  | One trie per matcher holds every binding. Steps with the same signature share a node                            | No binding matches on its own, and shared prefixes are walked once                                                     |
| A4  | Layers are added in order: core, browser listener, React, typed chain                                           | Each layer stays thin and depends only on the one below                                                                |
| A5  | Keys held together are called a combo                                                                           | Project vocabulary                                                                                                     |
| A7  | Small reusable pieces live in `src/shared/helpers`, one concern per file: `dev`, `environment`, `time`, `dom`   | Layers import them instead of repeating two-line checks, and each helper has one test file                             |
| A8  | `Host` is `"web"` or `"desktop"`, detected through the `isTauri` flag. Only Tauri 2 is supported                | Tauri 2 injects `window.isTauri`, the same check as `isTauri()` from `@tauri-apps/api`. Tauri 1 had no such flag       |
| A9  | A host is a scope, not a separate concept. Apps enable the `web` or `desktop` scope at startup                  | Scopes already switch bindings on and off and filter `list()`, so desktop-only combos need nothing new                 |
| A6  | There is no `hyper` modifier                                                                                    | It is a convention for all four modifiers at once, not a key. Writing `ctrl.alt.shift.meta` says the same thing        |

## Semantic types

All shared aliases live in `src/shared/types/semantic.ts` and are imported from there. Key and modifier names are derived from the constant lists in `src/shared/vocabulary.ts`, so the runtime list and the type cannot drift.

| ID  | Type                 | Meaning                                                                                                                            |
| --- | -------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| S1  | `Milliseconds`       | A length of time: timeouts, waits, hold thresholds, hold durations                                                                 |
| S2  | `MonotonicTime`      | A point in time from `performance.now()` or `KeyboardEvent.timeStamp`. Deadlines use it                                            |
| S3  | `KeyValue`           | The raw `KeyboardEvent.key`, before resolution                                                                                     |
| S4  | `KeyName`            | A closed union of accepted key names. A test proves `string` is not assignable to it                                               |
| S5  | `Modifier`           | A closed union of modifier names as written                                                                                        |
| S6  | `BindingID`          | Identifies a binding. Alternatives of one binding will share it                                                                    |
| S7  | `StepSignature`      | The trie key of a resolved step, covering wait, kind, threshold, modifiers and key                                                 |
| S8  | `Nullable<T>`        | A property that always exists but may hold no value. `?` is used only when a property may be omitted, such as `minDelay` on a step |
| S9  | Finite states        | `Platform`, `KeyPhase`, `KeySide`, `StepKind`, `HoldPhase` are literal unions                                                      |
| S10 | No branded types yet | Nothing mixes one kind of ID with another. Revisit if scopes or providers get IDs                                                  |

## Matching

| ID  | Decision                                                                                                          | Reason                                                                                                     |
| --- | ----------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| M1  | Match on `event.key`, lowercased. Letters ignore case, so Caps Lock does not matter                               | The spec matches by produced character. `event.code` is a later explicit mode                              |
| M2  | Shifted characters assume a US layout: `?` is Shift with `slash`, `!` is Shift with `1`, and so on                | `event.key` reports the character, not the key under it                                                    |
| M3  | `+` matches `plus` with Shift ignored, and Shift with `equals`                                                    | Shift only produces the character for `plus`                                                               |
| M10 | `dot` and `singlequote` are aliases of `period` and `quote`, folded to the canonical name when a step is resolved | Both spellings are common. One trie node per key keeps the overlap and duplicate rules simple              |
| M4  | Modifiers match exactly. Extra modifiers mean no match                                                            | Spec                                                                                                       |
| M5  | `lshift` and `rshift` track the side of the last Shift keydown                                                    | The side of the letter key says nothing about which Shift is held                                          |
| M6  | When Alt is held, the physical key from `event.code` is matched instead of the produced character                 | On a Mac, Option turns `k` into `˚`; the binding means the physical key. Assumes a US physical layout (M2) |
| M7  | Auto-repeat, IME composition and bare modifier keys never advance or break a sequence                             | Spec. A modifier pressed between steps must not reset progress                                             |
| M8  | A wrong key resets progress and starts a new attempt if it is itself a valid first step                           | Spec                                                                                                       |
| M9  | An unknown key name from untyped code throws when the matcher is built                                            | Spec says throw in development. The production warning belongs to the browser layer, which knows the mode  |

## Sequences and waits

| ID  | Decision                                                                                                                                    | Reason                                                                   |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Q1  | Default sequence timeout is 1000ms. A step arriving exactly at the timeout is too late                                                      | One rule for every deadline: due when `now >= deadline`                  |
| Q2  | `wait(ms)` is stored as `minDelay` on the next step. Arriving earlier is a wrong key                                                        | A wait is a property of the gap, not a step of its own                   |
| Q3  | A binding cannot start with a wait, and a wait must be shorter than the sequence timeout. Both throw                                        | Such bindings could never match                                          |
| Q4  | A binding that is also the start of a longer one waits for the window before firing, and fires at once when another key breaks the sequence | Spec overlap rule. The cost is a delay of up to the timeout on such keys |
| Q5  | `preventDefault` is requested only on the keydown that completes a match                                                                    | Spec. Partial sequences and waiting keys keep browser defaults           |

## Holds

| ID  | Decision                                                                                                                                               | Reason                                                                                                                                           |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| H1  | Default threshold is 500ms. `start` fires at the threshold with `duration` equal to it                                                                 | Spec                                                                                                                                             |
| H2  | `release` fires on keyup with the real duration, only after `start`                                                                                    | Spec                                                                                                                                             |
| H3  | A key matching a tap and a hold picks the tap when released early. The tap fires on release                                                            | Spec                                                                                                                                             |
| H4  | Another keydown cancels a hold that has not started. A started hold stays until its key is released                                                    | Pressing a second key shows the first was not a deliberate hold                                                                                  |
| H5  | The keydown that begins a hold requests `preventDefault`, so `hold("space")` does not scroll. The registry still skips it inside inputs                | Decided after the browser suite showed Space scrolling 630px during a hold. `MatchResult.holds` names the bindings so the skip rules apply (B27) |
| H6  | On a Mac, releasing Meta ends any hold whose step uses `meta` or `mod`, and counts as a tap if the threshold was not reached                           | Mac browsers send no keyup for the key while Cmd is held                                                                                         |
| H7  | While a started hold is down there is no sequence timeout; the clock for the next step starts at release. The next key may also arrive during the hold | Holding is deliberate, so a long hold must not expire the sequence it is part of                                                                 |
| H8  | A hold that is also the start of a longer sequence fires `start` at once                                                                               | Waiting for the sequence window would delay feedback the user is holding for                                                                     |
| H9  | `interrupt()` ends started holds with `release` and resets everything                                                                                  | Called on window blur, `visibilitychange` and focus moving between providers                                                                     |

## Browser

| ID  | Decision                                                                                                                                                       | Reason                                                                                                                      |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| B1  | `"typing"` is on by default and skips text-like `<input>`, `<textarea>`, `<select>` and anything inside a contenteditable region                               | Shortcuts must not steal keys the user is typing                                                                            |
| B2  | Input types button, checkbox, radio, submit, reset, file, range, color, image and hidden are not text. Every other type is                                     | Unknown and future types fall back to text, the safe side                                                                   |
| B3  | `allowInInputs` turns the default typing rule off. Listing `"typing"` in `except` turns it back on regardless                                                  | An explicit rule should always win over a default switch                                                                    |
| B4  | A modal is `dialog[open]`, `[aria-modal="true"]` or `[role="dialog"]` that is connected and has no `hidden` attribute on itself or an ancestor                 | `showModal()` and plain `open` both set the attribute, so one selector covers both. Hidden wrappers are closed modals       |
| B5  | A `<dialog>` opened with `show()` also counts as a modal                                                                                                       | The DOM exposes no reliable difference besides `:modal`, which happy-dom does not support                                   |
| B6  | With the `"modal"` rule, a target inside any open modal still fires. Targets outside it, the body and a null target are skipped                                | The modal is where the user is. Shortcuts bound to the page behind it must not fire                                         |
| B7  | `"disabled"` skips a target with the `disabled` attribute, `aria-disabled="true"` or a `fieldset[disabled]` ancestor. The `<legend>` exception is not modelled | The focused control is inert, so its shortcut should be too. The legend corner case is not worth the code until needed      |
| B8  | Rules receive the target as `Element` or `null`. Non-element nodes and `window` become `null`                                                                  | Keeps predicates simple; the typing rule needs an element anyway                                                            |
| B9  | The document for the modal check is the target's `ownerDocument`, falling back to the global `document`                                                        | Works for iframes and for events without a target                                                                           |
| B20 | The driver stamps every key input with its own `now()` instead of `event.timeStamp`                                                                            | One clock for events and timers, and tests can pass a controllable clock                                                    |
| B21 | A keydown rejected by `shouldHandle` is not fed to the matcher and interrupts all progress. Keyups are always fed                                              | A sequence continued inside a text field is a typo, but a hold started outside must still release                           |
| B22 | One timer at a time, re-armed after every state change from `nextDeadline`                                                                                     | A2: the matcher owns the schedule, the driver only sets one alarm                                                           |
| B23 | Fires caused by time (hold start, pending press, interrupt release) pass `null` as the event                                                                   | There is no keydown to prevent, and handlers can tell the two apart                                                         |
| B24 | `blur` is read from `window` and `visibilitychange` from `document`, whatever the listen target                                                                | Both are document-wide signals even when a provider element listens for keys                                                |
| B27 | A keydown that begins a hold is prevented when `shouldPrevent` accepts at least one of its bindings for the event target                                       | Same reasoning as B26 for holds, which fire later than the keydown                                                          |
| B26 | `preventDefault` is called only when `onFired` reports that a handler ran                                                                                      | The matcher cannot see skip rules; without this, a key typed into an input was lost whenever another binding allowed inputs |
| B25 | `createDriver` reads `window` only when called                                                                                                                 | Importing the browser entry during server rendering must not throw                                                          |

## Registry

| ID  | Decision                                                                                                                                                                                              | Reason                                                                                                                                                      |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | Press handlers receive `{ combo, event }` where `event` is null for time-driven fires and `trigger()`. Hold handlers receive `{ combo, phase, duration }`                                             | Nothing is faked: a pending press that fires from the timer has no keydown to hand over                                                                     |
| R2  | A binding without scopes is global. Scopes passed to `createRegistry` start enabled; `web` and `desktop` are built in and only the detected host starts enabled. Enabling one host disables the other | Host-specific combos need nothing beyond scopes, and an app can never be on both hosts                                                                      |
| R3  | Priority is compared among the bindings that fire on one key event; only the highest value runs. Default 0                                                                                            | Spec. Lower tiers stay registered so they take over when the higher one is disabled                                                                         |
| R4  | A keydown reaches the matcher when any active binding may handle its target. The skip rules are applied again per binding when it fires                                                               | One matcher serves bindings with different `except` and `allowInInputs` settings                                                                            |
| R5  | Fires without an event (timer, `trigger()`) check the skip rules against `document.activeElement`                                                                                                     | The best available stand-in for the key target                                                                                                              |
| R6  | `trigger()` on a hold binding calls the handler once with `start` and duration 0                                                                                                                      | Spec says run the handler once; `start` is the phase an action keys off                                                                                     |
| R7  | An invalid binding throws in development and in production warns and returns a dead handle whose `isEnabled()` is false                                                                               | Spec. The app keeps running and the handle still has a stable shape                                                                                         |
| R8  | The written combo orders modifiers `mod, ctrl, meta, alt, shift`. The Mac display uses Apple's order `⌃⌥⇧⌘`                                                                                           | Written form matches how people type chains; the label matches the menus users see                                                                          |
| R9  | Dev warnings: a combo bound twice in overlapping scopes (global overlaps everything, a strict prefix is not a duplicate), and a `web` binding on a combo browsers keep                                | Spec, plus the host question: the same `mod+w` is fine on the desktop                                                                                       |
| R11 | A hold whose `start` is skipped by the target rules is muted until its `release`, which is dropped too                                                                                                | Found by the vanilla demo: holding Space in a textarea opened the peek panel. The hold starts from a timer, so the focused element stands in for the target |
| R10 | Changing the active set rebuilds the matcher and resets progress                                                                                                                                      | Simple and correct: a sequence spanning a scope change has no defined meaning                                                                               |

## Chain

| ID  | Decision                                                                                                                                                            | Reason                                                                                                                                              |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| C1  | Stages exist only as types. The runtime is one immutable plain object with every member, cloned per call, and `createChain` returns it as `Shortcut<Scope>`         | The compiler checks the runtime object against the root stage structurally; no class per stage and nothing to keep in sync at runtime               |
| C2  | The only lie to the compiler is one overloaded `register` function in `chain.ts`, which claims the handle's `combo` literal and the handler's event type            | Both claims are the contract between the type-level template and `formatCombo` and cannot be proven; `as` is banned by lint, an overload is visible |
| C3  | The literal `combo` orders modifiers from the `Used` union through `ModifierPrefix`, not from the order they were written                                           | `shortcut.shift.mod.key("k")` and `formatCombo` both read `mod+shift+k`                                                                             |
| C4  | `wait(ms)` returns a step stage without `wait`, `then` or `on`, and the next `key` or `hold` carries `minDelay`                                                     | A wait is a property of the step that follows, so it cannot stand alone or repeat                                                                   |
| C5  | Each option can be used once; using any option removes `then`                                                                                                       | Options describe the whole binding, so they end the step list. The `Taken` union keeps the types simple                                             |
| C6  | Modifier getters and options are key-remapped mapped types over `ModifierDocs` and `OptionDocs` interfaces                                                          | JSDoc on the interface members survives into hover and autocomplete, verified through the language service                                          |
| C7  | `createChain(registry, scopes, bind?)` takes a `bind` that defaults to `registry.add`                                                                               | React registers in an effect and unbinds on unmount without a second builder                                                                        |
| C8  | The `then` getter trips `unicorn/no-thenable`; it is disabled inline                                                                                                | `then` returns a stage object, not a function, so `await` never treats a chain as a promise                                                         |
| C9  | A component with 200 chain bindings adds about 0.1s of `tsc` check time (1.20s against 1.08s)                                                                       | Measured with `--extendedDiagnostics`, three runs each. The stage types are cheap enough to keep                                                    |
| C10 | `.or` registers one binding per alternative and returns one handle that controls all of them. `combo` joins with `\|`, `display` with `/`, `trigger` runs the first | The matcher and registry stay unchanged; alternatives never collide in the duplicate check because their combos differ                              |

## React

| ID  | Decision                                                                                                                                                                                                            | Reason                                                                                                                                                                                  |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| X1  | A provider listens through React's `onKeyDown` and `onKeyUp` on a `display: contents` wrapper, not through a native listener on that element                                                                        | Native events do not bubble through portals: a keydown dispatched on a portal child never reaches the wrapper's native listener, while React's synthetic event does. Verified in a test |
| X2  | Each provider's registry listens on a detached element. The wrapper handler replays a copy of the key event onto it, with `target` overridden to the real element and `preventDefault` carried back to the original | The driver only takes a listen target. Keeping the real target makes the typing, modal and disabled rules work, including inside portals                                                |
| X3  | The outermost provider also takes keys from `window` whose target is `body` or `html`                                                                                                                               | With nothing focused, keydowns target `body`, which sits outside every React root. A global combo such as `mod+k` must still work then                                                  |
| X4  | A nested provider stops React propagation of a keydown unless its key and held modifiers match a step of a combo listed in `inherit`. Keyups always propagate                                                       | Outer bindings stay silent inside the region. Keyups must reach every region so a hold started elsewhere can release                                                                    |
| X5  | The first provider to see a keydown interrupts every other registry in the provider tree, once per event                                                                                                            | Focus moving between regions resets progress and ends holds. An inherited keydown continues to the outer provider without interrupting the inner one that just took it                  |
| X6  | `inherit` entries are checked once, a microtask after mount, against the outer registry's active combos. Unmatched entries warn in development                                                                      | Sibling bindings register in effects of the same commit, so a check during the provider's own effect would see too few combos                                                           |
| X7  | `ShortcutBoundary` stops React propagation of keydowns while `disabled` and lets keyups pass                                                                                                                        | Same reasoning as X4. The boundary never touches native propagation, so `onKeyDown` handlers inside it keep working                                                                     |
| X8  | The registry is created in the provider's layout effect. `useRegistry()` returns a facade that reads empty before mount, throws on writes before mount and keeps subscriptions across mount                         | Server rendering and the first client render have no DOM to listen on. Child effects run before the provider's passive effect but after its layout effect                               |
| X9  | `useBinding` registers in an effect keyed by the JSON of the definition's serialisable parts and keeps the handler in a ref. Predicates in `except` are captured at registration                                    | A new object literal per render must not re-register, and Strict Mode's double effect yields one binding and no duplicate warning                                                       |
| X10 | `scopes`, `sequenceTimeout`, `holdThreshold` and `platform` are read once at mount                                                                                                                                  | Recreating the registry on a prop change would drop every binding. Scopes change through `registry.enable` and `registry.disable`                                                       |
| X11 | `platform` is an optional provider prop that defaults to `detectPlatform()` during render                                                                                                                           | Lets a server and its client agree on `display` strings, and keeps tests deterministic across machines                                                                                  |

## Browser tests

| ID  | Decision                                                                                                                                                          | Reason                                                                                                                                                                |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| E1  | Playwright runs Chromium only with two workers. `e2e/serve.ts` bundles `src/index.ts` with `Bun.build` and serves `e2e/fixture/` on port 4173                     | One browser keeps the install small and the suite fast; the fixture imports the real bundle the way an app would                                                      |
| E2  | The fixture writes every fired event to `#log` as `combo phase duration` lines and every raw keydown to `#keys` with `repeat` and `defaultPrevented`              | Tests read text instead of hooking into page state, and the raw line proves what the browser saw                                                                      |
| E3  | Window blur during a hold is produced by focusing an iframe's `contentWindow`. `page.bringToFront()` and `window.blur()` deliver no `blur` in headless Chromium   | Tried on the headless shell and the full Chromium build; only focus moving into a frame fires a real `blur` on the top window                                         |
| E4  | True OS key auto-repeat is not reproducible under Playwright. The repeat test holds `s` for 800ms, proves one keydown arrived, then dispatches a synthetic repeat | `page.keyboard.down` sends one `keyDown` over CDP and never repeats it. The `Real key repeat` item in the plan stays open                                             |
| E5  | The modal test blurs the dialog's focused button before pressing the key, so the target is the body                                                               | B6 lets a key fired inside the open modal through, and `showModal()` moves focus to the close button. The test proves both sides                                      |
| E6  | A plain binding skipped inside an input keeps its typed character even when another binding uses `allowInInputs`                                                  | Found by the browser suite. `onFired` now reports whether any handler ran, and the driver only prevents a keydown that was handled (B26)                              |
| E7  | Playwright files are `*.spec.ts`, kept out of `tsconfig` includes. The `test` script runs `bun test __tests__` and `bun run e2e` is separate from `bun run check` | Bun's default pattern also matches `*.spec.ts`, so the runner must be pointed at `__tests__`. The suite needs a browser install the check script should not depend on |
