# @remcostoeten/use-shortcut

LLM-focused reference for implementing, extending, or integrating keyboard shortcut systems with this package.

## Package

- Name: `@remcostoeten/use-shortcut`
- Version: `1.2.0`
- Runtime: React (peer dependency)
- Key capabilities: chainable shortcuts, sequences/chords, scopes, conflict detection, recording mode, bulk maps, CLI scaffolding

## Core API

## Hooks and factories

- `useShortcut(options?)`
  Returns chainable builder (`$`) for React components.
- `createShortcut(options?)`
  Non-React builder. Caller handles lifecycle cleanup.
- `useShortcutMap(shortcutMap, options?)`
  Bulk registration helper in React.
- `createShortcutMap(shortcutMap, options?)`
  Bulk registration helper in non-React contexts.
- `registerShortcutMap(builder, shortcutMap)`
  Applies a map to an existing builder.

## Builder chain

- Modifiers: `.ctrl`, `.shift`, `.alt`, `.cmd`, `.mod`
- Keys: `.key("s")`
- Sequences: `.then("d")`, `.then("shift+d")`
- Exceptions: `.except("typing")` or custom predicate
- Scopes: `.in("editor")` or `.in(["editor", "navigation"])`
- Handlers: `.on(handler, options?)` or `.handle({ handler, ...options })`

## Runtime controls on builder

- `setScopes(scopes)`
- `enableScope(scope)`
- `disableScope(scope)`
- `getScopes()`
- `isScopeActive(scope)`
- `record({ timeoutMs?, target?, eventType? })`

## Handler options

- `preventDefault?: boolean` (default `true`)
- `stopPropagation?: boolean`
- `delay?: number`
- `disabled?: boolean`
- `except?: ExceptPreset | ExceptPreset[] | ExceptPredicate`
- `scopes?: string | string[]`
- `sequenceTimeout?: number`

## Hook options

- `debug?: boolean`
- `delay?: number`
- `ignoreInputs?: boolean`
- `target?: HTMLElement | Window | null`
- `eventType?: "keydown" | "keyup"`
- `disabled?: boolean`
- `activeScopes?: string | string[]`
- `sequenceTimeout?: number`
- `conflictWarnings?: boolean`
- `onConflict?: (conflict) => void`

## Shortcut map shape

```ts
const map = {
  save: { keys: "mod+s", handler: onSave },
  dashboard: { keys: ["g", "d"], handler: goDashboard },
}
```

`keys` supports:

- single combo string (`"mod+s"`)
- sequence array (`["g", "d"]`)
- sequence string (`"g d"` or `"g then d"`)

## Recommended Architecture (Scalable Apps)

Use a provider architecture with clear boundaries:

1. **Registry** (`registry.ts`): action ids, defaults, metadata, scope ownership
2. **Scope model** (`scopes.ts`): allowed scopes and defaults
3. **Runtime mapper** (`runtime.ts`): pure transform from registry + bindings + handlers -> `ShortcutMap`
4. **Storage adapter** (`storage.ts`): persistence for user key overrides
5. **Provider** (`provider.tsx`): state/actions/meta context + runtime registration lifecycle
6. **Public API** (`index.ts`): stable exports for app features

### Provider contract

Expose context with three parts:

- `state`: current scopes, bindings, enabled
- `actions`: set scopes, toggle scopes, change/reset bindings, enable/disable
- `meta`: derived information (`availableActions`, `hasBindingOverrides`)

This keeps UI/feature code decoupled from runtime implementation details.

## Architecture invariants

- Treat `registry.ts` as single source of truth.
- Keep handlers injectable and feature-owned.
- Persist only bindings, not handlers/functions.
- Use scopes for context activation instead of branching in handlers.
- Ensure registration cleanup happens when bindings/configuration changes.

## Extension protocol

When adding a shortcut action:

1. Add action metadata to `registry.ts`.
2. Inject corresponding handler through provider usage.
3. Assign explicit scope ownership.
4. Expose configurable bindings if needed (`setBinding`, `resetBinding`).
5. Add tests for map generation and scope behavior.

When replacing persistence:

1. Keep `ShortcutBindings` shape stable.
2. Swap only `storage.ts` implementation.
3. Keep provider API (`actions`) unchanged.

## Anti-patterns

- Scattered shortcut declarations across many pages.
- Untyped scope strings outside central scope model.
- Business logic in registry (registry should stay declarative).
- Persisting executable code.
- Global shortcuts without explicit scope ownership.
